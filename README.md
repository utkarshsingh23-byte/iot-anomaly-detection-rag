# IoT RAG Anomaly Shield

An end-to-end IoT network threat detection and explanation project that combines a CNN-LSTM anomaly detector, a Streamlit operations dashboard, and retrieval-augmented explanations generated by local Ollama models.

The system samples CICIoT2023 traffic windows, predicts **Normal**, **DDoS**, or **Botnet** traffic, retrieves relevant cybersecurity guidance, and presents incident analysis and response recommendations.

## Features

- CNN-LSTM detector for 10-timestep IoT traffic windows with 38 features
- Three-class classification: Normal, DDoS, and Botnet
- Real test-sample simulation instead of manually fabricated traffic values
- Streamlit dashboard with live predictions, probabilities, flow logs, and health indicators
- Preset and custom attack scenarios
- FAISS semantic retrieval over MITRE ATT&CK, CISA, and Cyber Swachhta Kendra material
- Streaming, local LLM explanations through Ollama
- Hallucination-resistant explanation validation and fallback handling
- Reproducible batch and non-LLM evaluation workflows

## Architecture

```text
CICIoT2023 processed test windows
              |
              v
CNN-LSTM detector ----------------> Predicted class + probabilities
              |                                  |
              |                                  v
              |                        Feature and class query
              |                                  |
              |                                  v
              |                         FAISS retrieval
              |                                  |
              v                                  v
     Streamlit dashboard <--------- Ollama explanation
```

## Requirements

- Windows 10/11
- Python 3.11 recommended
- 8 GB RAM minimum; 16 GB recommended for the dashboard and local embedding model
- [Ollama](https://ollama.com/) for local explanation generation
- Internet access only during package/model/reference downloads

Core Python packages include:

- `torch`, NumPy, pandas, scikit-learn, joblib
- Streamlit and Plotly
- FAISS, PyMuPDF, Sentence Transformers
- Requests and SciPy

## Quick Start

### 1. Create a virtual environment

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

If PowerShell blocks the activation script:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### 2. Install dependencies

Install the component dependencies and the packages used by the RAG dashboard:

```powershell
python -m pip install -r cnn_lstm_component\requirements.txt
python -m pip install streamlit plotly requests faiss-cpu pymupdf sentence-transformers beautifulsoup4 tqdm scipy
```

For NVIDIA GPU acceleration, install the PyTorch build appropriate for your CUDA environment. CPU-only PyTorch is sufficient.

### 3. Configure and run Ollama

Start Ollama, then pull at least the default explanation model:

```powershell
ollama serve
ollama pull llama3.2:3b
```

The dashboard also supports:

```text
llama3.2:3b
gemma2:2b
phi3:mini
```

Pull an optional model before selecting it:

```powershell
ollama pull gemma2:2b
ollama pull phi3:mini
```

Ollama must remain available at `http://localhost:11434`.

### 4. Build the RAG index

The repository may already contain `rag/rag_store/kb.index` and `chunks.json`. To rebuild them from the source documents:

```powershell
python rag\build_index.py
```

This downloads `sentence-transformers/all-MiniLM-L6-v2` on first use if it is not already cached.

### 5. Launch the dashboard

```powershell
python -m streamlit run dashboard\app.py
```

Open the local URL printed by Streamlit, normally `http://localhost:8501`.

## Using the Dashboard

1. Select **Preset** or **Custom** in the sidebar.
2. Start the simulation.
3. The dashboard moves through Normal, DDoS, Botnet, and recovery phases.
4. Select whether explanations should use RAG retrieval.
5. Choose an Ollama model.
6. Review prediction confidence, class probabilities, traffic details, and incident guidance.

The dashboard automatically falls back to a concise local explanation when Ollama or retrieval is unavailable.

## Standalone CNN-LSTM Inference

The extracted component accepts raw traffic rows containing all 38 ordered feature columns:

```powershell
python cnn_lstm_component\inference\predict.py traffic.csv
```

The CSV must contain at least 10 complete rows. A CSV label column is optional and is ignored.

Python API example:

```python
import pandas as pd
from cnn_lstm_component.inference.predict import load_model, predict_rows

traffic = pd.read_csv("traffic.csv")
model, scaler = load_model()
results = predict_rows(traffic, model, scaler)

for result in results:
    print(result)
```

Component details and known extraction limits are documented in [cnn_lstm_component/README.md](cnn_lstm_component/README.md).

## RAG Data Setup

The RAG index reads:

- MITRE ATT&CK technique text in `data/rag_documents/mitre_attack/`
- Cyber Swachhta Kendra text in `data/rag_documents/csk/`
- CISA PDFs in `data/rag_documents/cisa/`

To refresh downloaded web sources:

```powershell
python download_mitre.py
python download_csk.py
python rag\build_index.py
```

The scripts send read-only requests to public web sources and do not require API keys. Downloaded content may change independently over time.

## Evaluation

Start Ollama before running the batch evaluation:

```powershell
python rag\run_batch_evaluation.py
```

The batch workflow compares detector-only context and RAG-assisted explanations across multiple local Ollama models and writes CSV results under `rag/`.

Run the non-LLM baselines:

```powershell
python rag\run_non_llm_evaluation.py
```

Summarize a metrics CSV:

```powershell
python rag\summarize_evaluation.py `
  --metrics-csv rag\evaluation_metrics.csv `
  --comparison-csv rag\evaluation_results.csv `
  --baselines-csv rag\evaluation_non_llm.csv `
  --output-csv rag\evaluation_summary.csv `
  --charts-dir rag\evaluation_charts
```

Example explanation-metric evaluation:

```powershell
python rag\evaluate_explanations.py `
  --comparison rag\evaluation_results.csv `
  --baselines rag\evaluation_non_llm.csv `
  --output rag\evaluation_metrics.csv
```

## Model Details

- Input shape: `(batch_size, 10, 38)`
- Architecture: two Conv1D blocks, BatchNorm, ReLU, max pooling, dropout, and two LSTM layers
- Hidden sizes: 128 and 64
- Output: 3 logits converted to class probabilities with softmax
- Checkpoint: `cnn_lstm_component/models/best_model.pth`
- Feature scaler: `cnn_lstm_component/preprocessing/scaler.pkl`
- Test windows: `data/processed/X_test.npy`
- Test labels: `data/processed/y_test.npy`

The dashboard loads real test windows and never treats the selected attack scenario label as a model prediction; it reports the model's own predicted class and confidence.

## Troubleshooting

### Ollama is unavailable

Verify the service and model:

```powershell
ollama list
ollama serve
ollama pull llama3.2:3b
```

The dashboard and RAG CLI should remain usable for detection and retrieval, but explanation generation will not work until Ollama responds.

### FAISS index is missing

Run:

```powershell
python rag\build_index.py
```

Ensure at least one MITRE `.txt`, CSK `.txt`, or CISA `.pdf` exists under `data/rag_documents/`.

### Processed test data is missing

The simulator requires `data/processed/X_test.npy`, `data/processed/y_test.npy`, and `data/processed/feature_names.txt`. Restore these from the original model preprocessing workflow before starting the dashboard.

### PyTorch or CUDA installation fails

First verify the Python and package versions:

```powershell
python --version
python -m pip show torch
```

Use a supported PyTorch build for the installed Python version. CPU-only execution is sufficient and does not require CUDA.

## Data and Security Notes

- Do not commit API keys or Ollama credentials.
- Keep the `.env`, virtual environments, local caches, and secrets excluded as configured in `.gitignore`.
- Treat generated explanations as decision support, not an autonomous incident-response system.
- Verify mitigation guidance against the source material and organizational policies.
- Raw source datasets and large generated artifacts should remain appropriately governed and excluded from source control.
